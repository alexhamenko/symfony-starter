# LinguaSchool: етап 7. Навчальний контент - детальний план

Oct 9, 2026 · @Alex Hamenko

Після етапу 7 (приблизно 3-4 тижні) студент проходить self-study курси з різними типами вправ, отримує домашні завдання від викладача, бачить прогрес за рівнем CEFR і тренує слова з інтервальними повтореннями.

Попередній: [етап 6](stage-6.md). Модулі: `Learning` (шари DDD) і `Vocabulary` (середній). Усе через API кабінету.

## Етап 7. Навчальний контент (≈3-4 тижні)

### 7.1 Модель курсу (≈3 дні)

| Сутність | Поля |
| --- | --- |
| `Course` (Learning) | id, level (`CefrLevel`), isPublished; переклади |
| `Module` | id, course, position; переклади |
| `CourseLesson` | id, module, position, estimatedMinutes; переклади |
| `Exercise` | id, lesson, position, type, payload (JSON) |
| `Enrollment` | id, studentId, courseId, startedAt, completedAt |

1. `Course` з `Learning` і курс-тизер з `Catalog` (етап 2) - різні сутності різних модулів. Зв'язок - за ідентифікатором або ключем.
2. Ієрархія з упорядкуванням (`position`), каскади і `orphanRemoval` - де доречно, а де ні.
3. Доступ до self-study - лише з активною підпискою (фасад з етапу 6) або в межах оплаченого періоду після скасування.

**Що вивчаєте:** складні Doctrine-моделі, агрегати, впорядковані колекції.

### 7.2 Типи вправ (≈4 дні)

1. Типи: single/multiple choice, gap fill, matching, word order, audio (прослухати й обрати). `payload` - JSON у БД, у PHP - типізовані `readonly` DTO.
2. Серіалізація з discriminator (`#[DiscriminatorMap]` у Serializer) за полем `type`; валідація кожного типу своїми constraints.
3. Перевірка відповідей - стратегія на тип: сервіси з тегом (`#[AutoconfigureTag]`, `#[AsTaggedItem]`) і `ServiceLocator` за типом. Новий тип вправи = новий клас, без змін у старих.
4. API: `GET /api/learning/lessons/{id}` (вправи без правильних відповідей!), `POST /api/learning/exercises/{id}/attempts`.

**Що вивчаєте:** Serializer з discriminator, Doctrine JSON, tagged services, ServiceLocator.

### 7.3 Спроби і прогрес (≈3 дні)

| Сутність | Поля |
| --- | --- |
| `ExerciseAttempt` | id, studentId, exerciseId, answer (JSON), isCorrect, score, createdAt |

1. Прогрес уроку, модуля і курсу; прогрес рівня CEFR (рівень = 54-59 уроків, включно з індивідуальними з `Scheduling` через подію `LessonCompleted`).
2. Агрегати рахуйте запитами (DQL з `GROUP BY` або DTO через `NEW`), а не перебором колекцій у PHP; порівняйте в профайлері.
3. `GET /api/me/progress` - read model, за потреби кешований з інвалідацією на нових спробах.

**Що вивчаєте:** DQL-агрегації, read models, DTO-проєкції.

### 7.4 Домашні завдання і файли (≈3 дні)

| Сутність | Поля |
| --- | --- |
| `Homework` | id, lessonId, teacherId, studentId, task, dueAt, status, submission (текст + файли), feedback, grade |

1. Викладач створює домашку після уроку (`completed`), студент здає текст і файли, викладач перевіряє. Voters: лише учасники уроку.
2. Файли - `league/flysystem-bundle` (перевірте сумісність): локальний адаптер у dev, S3-сумісне сховище (MinIO у compose) як prod-подібне. Перенесіть фото викладачів з етапу 2 на Flysystem.
3. Завантаження: constraint `File` (розмір, MIME), імена файлів генеруються, оригінальна назва - у метаданих. Скачування - через контролер із перевіркою доступу або підписаний тимчасовий URL, не прямим посиланням.

**Що вивчаєте:** Flysystem, завантаження і віддача файлів (`BinaryFileResponse`, `StreamedResponse`), безпека файлів.

### 7.5 Тренажер слів (≈4 дні)

| Сутність | Поля |
| --- | --- |
| `Word` | id, term, transcription, audio, level; переклади (значення, приклади) |
| `WordSet` | id, title, level, words; переклади |
| `UserWordProgress` | id, studentId, wordId, easeFactor, interval, repetitions, dueAt, lastReviewedAt |

1. SM-2 як чиста доменна логіка в `Vocabulary/Domain`: оцінка відповіді 0-5 -> новий `easeFactor`, `interval`, `dueAt`. FSRS - опційно, за інтерфейсом алгоритму.
2. API: черга слів на сьогодні (`dueAt <= now` у таймзоні студента), відповідь, додавання набору чи власного слова.
3. Щоденний дайджест "N слів чекають на повторення" через Scheduler (з етапу 5), з урахуванням таймзони.
4. Доступ - за правилами підписки (як 7.1).

**Що вивчаєте:** алгоритмічна доменна логіка, ретельні unit-тести, ефективні вибірки за датою.

### 7.6 Адмінка контенту (≈2 дні)

1. EasyAdmin: курси -> модулі -> уроки -> вправи.
2. Редагування `payload` вправи: форма залежить від типу - form events (`PRE_SET_DATA`, `PRE_SUBMIT`) або окремий FormType на тип через ту саму tagged-стратегію.
3. Імпорт слів з CSV консольною командою (з прогрес-баром і звітом про помилки).

**Що вивчаєте:** динамічні форми (form events), консольні команди з I/O.

### 7.7 Тести й готовність етапу 7 (≈3 дні, паралельно з рештою)

1. **Unit:** перевірка відповідей для кожного типу вправи, SM-2 (послідовності оцінок), розрахунок прогресу.
2. **Integration:** серіалізація/десеріалізація всіх типів `payload`, DQL-агрегації прогресу, Flysystem з in-memory адаптером.
3. **Functional (API):** проходження уроку, правильні відповіді не потрапляють у відповідь API, домашка (створення, здача з файлом, чужа домашка - 403), черга слів.

**Готовність етапу 7**

- [ ] Self-study курс із щонайменше п'ятьма типами вправ, прогрес зберігається
- [ ] Новий тип вправи додається без змін в існуючих класах
- [ ] Прогрес рівня CEFR з урахуванням індивідуальних уроків
- [ ] Домашні завдання з файлами через Flysystem, доступ лише учасникам
- [ ] Тренажер слів на SM-2 з чергою і щоденним нагадуванням
- [ ] Доступ до контенту залежить від підписки
- [ ] `make qa` і `make test` зелені
