# LinguaSchool: етап 11 (опційно). Vue-фронтенд - детальний план

Oct 9, 2026 · @Alex Hamenko

Після етапу 11 (приблизно 3-4 тижні) плейсхолдери `data-island` на публічних сторінках стають Vue-острівцями, а кабінет на `/app/*` - SPA поверх готового API. Бекенд майже не змінюється: це перевірка, наскільки добре спроєктовано API.

Попередній: [етап 10](stage-10.md). Етап опційний: перш ніж починати, вирішіть, чи потрібен Vue взагалі (див. 11.1).

## Етап 11. Vue-фронтенд (≈3-4 тижні)

### 11.1 Рішення: Vue чи Live Components (≈0,5 дня)

1. Альтернатива - Symfony UX Live Components: інтерактивність на PHP без окремого фронтенду. Для форм і тесту рівня цього може вистачити.
2. Порівняйте на одному острівці (наприклад, `LevelTest`): обсяг коду, SEO, тестування, досвід розробки. Зафіксуйте рішення в ADR-нотатці.
3. Далі план описує варіант із Vue.

### 11.2 Збірка: Vite замість AssetMapper (≈0,5-1 день)

1. `pentatrion/vite-bundle` + `vite-plugin-symfony`, Node-сервіс у compose для dev-сервера Vite, TypeScript.
2. У `base.html.twig` `importmap()` замінюється на `vite_entry_link_tags()`/`vite_entry_script_tags()`. Tailwind і daisyUI переходять на npm-пакети і Vite-плагін; standalone-бінарник і `tailwind/plugins/` прибираються.
3. Prod-збірка: Node-стадія в `Dockerfile`, CI збирає фронтенд перед образом.

**Що вивчаєте:** інтеграція Vite із Symfony, багатостадійний Docker build.

### 11.3 Острівці на публічних сторінках (≈1 тиждень)

1. Монтування: один entry шукає елементи з `data-island`, бере `data-props` (JSON) і монтує відповідний компонент. SSR-розмітка всередині - fallback без JS і для SEO.
2. Острівці: `CoursesCarousel`, `Testimonials`, `LevelTest` (через API тесту рівня, при потребі - нові ендпоінти), форма пробного уроку (через `POST /api/leads` з етапу 3), `SeatCounter` (Mercure з етапу 8).
3. Lazy-завантаження острівців (dynamic import), щоб не погіршити Lighthouse.

**Що вивчаєте:** прогресивне покращення, контракт props між Twig і Vue.

### 11.4 SPA кабінету (≈2 тижні)

1. `/app/*`: Vue Router, Pinia (стан сесії і користувача), TanStack Vue Query (кеш API-запитів), vue-i18n (ті самі локалі `uk`/`en`).
2. Типи API - генерація з OpenAPI API Platform (`openapi-typescript`) у CI; розбіжність схеми і фронтенду ламає збірку.
3. Автентифікація - сесійні cookie і CSRF, як заплановано на етапі 4; без JWT. Обробка 401/403 і прострочених сесій.
4. Екрани: розклад і бронювання, баланс і оплата, self-study, тренажер слів, клуби, профіль.
5. Realtime: підписка на приватні топіки Mercure.

**Що вивчаєте:** SPA поверх Symfony API, генерація типів з OpenAPI, cookie-автентифікація в SPA.

### 11.5 Тести фронтенду (≈3 дні)

1. Vitest для компонентів і composables.
2. Playwright для наскрізних сценаріїв: пробний урок з головної, логін -> бронювання -> скасування, проходження тесту рівня. Запуск у CI проти зібраного образу.
3. Перевірка, що публічні сторінки досі працюють без JavaScript (Playwright з вимкненим JS).
